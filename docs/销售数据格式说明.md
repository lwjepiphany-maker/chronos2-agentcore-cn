# 销售数据格式说明

Agent 读取的是由 `iac/prepare_data.py`（或前端"上传销售 Excel"）从 Excel 转换出的日销量表。Excel 需满足以下要求。

## 一、Excel 结构

- 文件格式：`.xlsx` 或 `.xls`
- 可以一个 sheet 放全部门店，也可以每个 sheet 一家门店（转换时会把所有 sheet 合并），sheet 名不限
- 第一行为列名，之后每行 = 某门店、某商品、某一天的销量

| 列名 | 必需 | 类型 | 说明 |
|---|---|---|---|
| 记账日期 | 必需 | 日期 | 如 `2026-05-24`、`2026/5/24`，Excel 日期格式也可以。无法解析的行会被丢弃；超过 1% 解析失败则整体报错 |
| 门店代码 | 必需 | 整数 | 如 `1`～`6` |
| 商品代码 | 必需 | 整数 | 如 `12080084` |
| 销售数量 | 必需 | 数字 | 当天销量，可为小数 |
| 门店类型 | 可选 | 文本 | 如 `社区店` |
| 天气 | 可选 | 文本 | 如 `晴`、`多云`、`小雨`，用于带天气的预测 |
| 温度 | 可选 | 文本 | 如 `3℃~6℃`，转换时拆成最低/最高温 |
| 星期 | 可选 | 文本 | 如 `星期一` |
| 节假日 | 可选 | 文本 | `工作日` / `周末` / `周末调班` / 节日名（`劳动节`、`清明节`…）；缺失时系统用离线节假日日历自动补 |
| 促销类型 | 可选 | 文本 | `促销价` / `换购` / `折扣` / `立减` / `赠品`；无促销留空。同一天多种活动取第一种 |
| 促销数量 | 可选 | 数字 | 当天以促销方式售出的数量 |
| 优惠金额 | 可选 | 数字 | 当天促销优惠总额（元） |
| 促销单据类别 | 可选 | 文本 | 如 `组合商品促销` / `指定商品促销` / `品类全场促销` |
| 门店售价 | 可选 | 数字 | 当天售价（元） |
| 商品品牌 | 可选 | 文本 | 如 `蒙牛（常温）` |
| 门店商品ABC属性 | 可选 | 文本 | `A` / `B` / `C` / `D` |

列名别名：`门代码` 等同 `门店代码`，`售价` 等同 `门店售价`。文件里结构不同的 sheet（如单独的促销流水明细）会被自动跳过，只合并含必需列的 sheet。

列名必须与上表一致（中文全称）。可选列缺失时留空即可，不影响单品预测和批量预测；促销、节假日、价格、天气等列存在时，"带业务因素的预测"会把它们作为协变量使用，精度更好。

## 二、数据内容要求

| 项目 | 要求 | 原因 |
|---|---|---|
| 粒度 | 每行一天一店一品；同一天同店同品多行会自动累加 | 模型按日序列预测 |
| 无销售的日期 | 可以没有该行，转换后视为销量 0 | 不需要手工补零 |
| 历史长度 | 最近一段**连续日期**建议 ≥ 60 天，至少 30 天 | 预测默认用最近 60 天历史 |
| 多段数据 | 允许（如 2025 春季 + 2026 春季），但**只有最后一段连续日期会被用于预测** | 避免把中间空档当成零销量 |
| 更新频率 | 建议每天或每周覆盖上传最新全量 | 预测起点 = 数据最后一天的次日 |

"连续日期"指数据中出现过的日期之间没有断档。例如数据到 10 月 15 日，之前 60 天每天都有记录（任意门店任意商品有一行即可），那么预测用的就是 8 月 17 日～10 月 15 日。

## 三、预测的时间口径

- **预测起点 = 数据中最后一个日期的次日。** Excel 最后一天是 10 月 15 日，"未来 7 天"= 10 月 16 日～10 月 22 日。
- 与上传或提问的"今天"无关：数据停在 5 月 24 日，不管几号问，下周都指 5 月 25 日～31 日。要预测最新一周，就上传最新数据。
- 带天气的预测会按这 7 个日期去取 Open-Meteo 的天气：未来日期用预报（最多 16 天），已过去的日期用历史实况。
- 节假日按中国法定节假日离线日历自动判断（含调休）；**未来促销计划需要在提问时告知**（如"5 月 29～31 日促销价"），系统按该商品历史促销的平均优惠和促销量构造协变量；不说明则按无促销预测。
- 预测长度：模型单次最多 1,024 天，建议 7～30 天；历史窗口默认 60 天。
- 返回的 P10 / P50 / P90 分别对应"保守 / 常规 / 安全上限"，补货建议用 P50 做常规量、P90 做安全库存上限。

## 四、转换与上传方式

| 方式 | 命令 / 操作 |
|---|---|
| 部署时 | `python iac/prepare_data.py 门店销售数据.xlsx data/sales_daily.parquet`，再由 `deploy.sh` 上传 |
| 日常更新（推荐） | 前端侧栏"上传销售 Excel"→"转换并上传"，Agent 30 秒内生效 |
| 命令行更新 | `python iac/prepare_data.py 新数据.xlsx data/sales_daily.parquet && aws s3 cp data/sales_daily.parquet s3://<DataBucket>/data/sales_daily.parquet` |

数据桶开启了版本控制，上传错误可在 S3 控制台恢复上一版本。转换失败时会给出中文提示（缺列、日期格式、无有效行）。

## 五、商品主数据与库存快照（补货决策用，可选）

补货量 = 预测 − 可用库存，并受保质期、到货周期、箱规约束，需要两张额外的表。客户未提供前，系统用 `tools/mock_master_data.py` 生成的**模拟数据**演示（输出里会标注"演示用模拟数据"）。

**商品主数据**（一个 sheet）：

| 列名 | 必需 | 说明 |
|---|---|---|
| 商品代码 | 必需 | 与销售数据一致 |
| 保质期(天) | 必需 | ≤ 7 天视为短保，按 P50 备货；更长按 P90 |
| 到货周期(天) | 建议 | 下单到到货的天数，默认 2 |
| 补货间隔(天) | 建议 | 多久补一次，默认 7 |
| 箱规 | 必需 | 每箱件数 |
| 起订量(箱) | 可选 | 默认 1 |
| 品牌 / 品类 | 可选 | 便于汇总 |

**库存快照**（一个 sheet，建议每天更新）：

| 列名 | 必需 | 说明 |
|---|---|---|
| 门店代码、商品代码 | 必需 | — |
| 现有库存 | 必需 | 件 |
| 在途 | 可选 | 已下单未到货的件数 |
| 最早到期日 | 可选 | 若落在补货覆盖期内，这批库存视为不可用 |
| 快照日期 | 可选 | — |

转换上传：`python iac/prepare_master.py 商品主数据与库存.xlsx data/master && aws s3 cp data/master/ s3://<DataBucket>/master/ --recursive`。Agent 每 60 秒刷新一次。

补货公式：覆盖天数 D = min(补货间隔 + 到货周期, 保质期 − 到货周期 − 1)；需求 = 到货后 D 天预测分位数之和；补货量 = max(0, 需求 − 可用库存 − 在途)，按箱规向上取整、不低于起订量；同时给出"若按 P90 多备可能过期的量"。
