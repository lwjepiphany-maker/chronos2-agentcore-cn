# 部署前检查清单（现场用）

按 README"部署"一节的 5 步执行前，逐项确认。全部打勾后，首次部署约 20～30 分钟。

## 一、客户账号（中国区）

- [ ] 已开通 Amazon Bedrock AgentCore：`aws bedrock-agentcore-control list-agent-runtimes --region cn-northwest-1` 返回空列表而不是报错
- [ ] 部署凭证有权限：CloudFormation、IAM（建角色）、ECR、S3、CodeBuild、Lambda、Secrets Manager、bedrock-agentcore-control、CloudWatch Logs、X-Ray
- [ ] `aws sts get-caller-identity --region cn-northwest-1` 显示的是客户账号
- [ ] 账号内没有同名残留：`chronos2-agentcore` 栈、`chronos2-agent-data-<账号>` 桶、`chronos2-forecast` / `chronos2-agent` ECR 仓库、Identity provider `chronos2-llm-key`（有则先删，或换 `PREFIX`）

## 二、部署机

- [ ] AWS CLI v2（`aws --version`），已配置中国区凭证
- [ ] Python 3.10+，`pip install pandas pyarrow openpyxl boto3` 成功
- [ ] 能访问 github.com（`git clone` 测试）；否则改用 zip 离线部署（README"离线部署"）
- [ ] 跑测试脚本还需要：`pip install mcp mcp-proxy-for-aws`（`tests/bench.py` 直连预测服务时用；`tests/agent_cloud_test2.py` 只需 boto3）

## 三、客户提供的材料

- [ ] 大模型 API Key（PPIO / DeepSeek 官方 / 百炼等 OpenAI 兼容接口），余额充足；非 PPIO 时准备好 `LLM_BASE_URL` 和 `LLM_MODEL`
- [ ] 门店销售 Excel，列名对照 `docs/销售数据格式说明.md`（必需：记账日期、门店代码、商品代码、销售数量）
- [ ] 门店所在城市（`STORE_CITY`，默认西安）
- [ ] 商品主数据与库存 Excel（可选；没有就用 `tools/mock_master_data.py` 生成模拟数据，Agent 回答会标注"模拟数据"）

## 四、部署中

- [ ] 第 2 步 `deploy.sh` 期间可在 CloudWatch 日志组 `/aws/codebuild/chronos2-agentcore-image-build` 看构建进度
- [ ] 若构建超时（镜像站慢），CloudFormation 自动回滚；直接重跑同一命令，已构建好的镜像会复用
- [ ] 栈创建完成后 `deploy.sh` 会自动上传销售数据并打印 Agent ARN、数据桶名、前端命令

## 五、部署后验证

- [ ] `python tests/agent_cloud_test2.py <Agent ARN>`：三轮对话（预测 → 算箱数 → 画图）全部返回
- [ ] 前端 `streamlit run frontend/app.py -- --agent-arn <ARN> --data-bucket <桶> --region cn-northwest-1` 打开，侧栏显示大模型名称
- [ ] 依次试：预测 → 补货 → 促销对比 → 回测 → 批量报表（出现下载按钮）→ 画图
- [ ] CloudWatch → Transaction Search 能看到 `service.name=chronos2_agent` 的调用链

## 六、交接给客户

- [ ] 记录：Agent ARN、预测服务 ARN、数据桶名、栈名
- [ ] 说明：更新数据（前端上传 / 定时导出）、换 Key（重跑 deploy.sh）、升级（改 IMAGE_TAG）、删除（delete-stack + 删桶）
- [ ] 提醒：对话内容会发送给大模型服务商；主数据为模拟数据时补货结果仅供演示
