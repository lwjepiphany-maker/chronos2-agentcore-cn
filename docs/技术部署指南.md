# 部署指南：Chronos-2 销量预测 + Agent on Amazon Bedrock AgentCore（中国区）

两个阶段，可以只部署阶段 1（预测服务给 Claude/Kiro 等客户端直连），也可以两个都部署（业务人员通过云上 Agent 对话）。

```
阶段 1                                阶段 2
Runtime②：Chronos-2 预测 MCP   ←──   Runtime①：Agent（DeepSeek 等 LLM + 取数工具）
（CPU 推理，IAM 鉴权）                 （IAM 鉴权，API Key 托管在 AgentCore Identity）
```

## 前提条件

| 项目 | 要求 |
|---|---|
| AWS 账号 | 中国区（宁夏 cn-northwest-1 或北京 cn-north-1），已开通 Bedrock AgentCore |
| 部署机权限 | ECR、IAM（建角色）、bedrock-agentcore-control、S3、CloudWatch Logs |
| 本机工具 | AWS CLI v2（最新版，需含 `bedrock-agentcore-control`）、Docker 或 finch（能构建 linux/arm64）、Python 3.12 |
| Python 包 | `pip install modelscope pandas pyarrow openpyxl boto3 mcp mcp-proxy-for-aws` |
| LLM | 任一 OpenAI 兼容接口 + API Key（已验证 PPIO 的 `deepseek/deepseek-v4-flash-0731`） |

## 部署步骤

```bash
# 0. 修改参数（区域、仓库名、桶名、LLM 地址和模型）
vi deploy/env.sh
source deploy/env.sh

# 1. 阶段 1：预测服务（约 20 分钟，主要是 800MB 镜像推送）
bash deploy/01_deploy_chronos_runtime.sh
python tests/bench.py --runtime-arn "$(cut -d= -f2 deploy/.chronos_runtime.env)" --repeat 2   # 验证

# 2. 阶段 2：Agent（约 8 分钟）
python deploy/prepare_data.py 门店销售数据.xlsx data/sales_daily.parquet          # Excel → parquet
LLM_API_KEY='sk_xxx' bash deploy/02_deploy_agent_runtime.sh data/sales_daily.parquet
python tests/agent_cloud_test.py "$(cut -d= -f2 deploy/.agent_runtime.env)"        # 3 轮对话验证
```

脚本可重复执行：资源已存在时会更新镜像/策略而不是报错。

## 调用方式

**客户端直连预测服务（阶段 1）**，以 Claude Code 为例：

```bash
RUNTIME_ARN=$(cut -d= -f2 deploy/.chronos_runtime.env)
URL="https://bedrock-agentcore.${AWS_REGION}.amazonaws.com.cn/runtimes/$(python3 -c "import urllib.parse,sys;print(urllib.parse.quote(sys.argv[1],safe=''))" "${RUNTIME_ARN}")/invocations?qualifier=DEFAULT"
claude mcp add --scope user chronos2-forecast -- uvx mcp-proxy-for-aws@latest "${URL}" --service bedrock-agentcore --region "${AWS_REGION}"
```

**业务系统调用 Agent（阶段 2）**，Python：

```python
import boto3, json, uuid
rt = boto3.client("bedrock-agentcore", region_name="cn-northwest-1")
r = rt.invoke_agent_runtime(
    agentRuntimeArn=AGENT_RUNTIME_ARN, qualifier="DEFAULT",
    runtimeSessionId=session_id,          # 同一会话复用，Agent 会记住上下文；至少 33 个字符
    runtimeUserId=user_id,                # 必填：没有它 Agent 取不到 LLM API Key
    contentType="application/json", accept="application/json",
    payload=json.dumps({"prompt": "预测5号店商品12080084下周销量"}).encode())
print(json.loads(r["response"].read())["result"])
```

调用方需要 IAM 权限 `bedrock-agentcore:InvokeAgentRuntime`（资源为 Runtime ARN 及 `ARN/*`）。

## 日常运维

| 操作 | 命令 |
|---|---|
| 更新销售数据 | `python deploy/prepare_data.py 新数据.xlsx data/sales_daily.parquet && aws s3 cp data/sales_daily.parquet s3://${DATA_BUCKET}/${DATA_KEY}`（新会话生效） |
| 更新 Agent 代码 | 改 `IMAGE_TAG` 后重跑 `02_deploy_agent_runtime.sh` |
| 轮换 LLM Key | 重跑 `02_...`（脚本会 update provider），或单独 `aws bedrock-agentcore-control update-api-key-credential-provider` |
| 看日志 | CloudWatch 日志组 `/aws/bedrock-agentcore/runtimes/<runtime-id>-DEFAULT` |
| 看链路追踪 | CloudWatch 控制台 → GenAI Observability（或 X-Ray Traces），按 service.name=Agent Runtime 名过滤；需账号已开启 Transaction Search |
| 天气数据 | Agent 内置 Open-Meteo 天气 MCP（`app_agent/weather_mcp.py`，stdio 子进程，免费无 Key），城市由 `STORE_CITY` 配置；Runtime 需能出站访问 api.open-meteo.com |
| Agent 画的图 | `s3://${DATA_BUCKET}/charts/`，调用方用 IAM 凭证下载 |
| 看用量/费用 | CloudWatch 指标 `AWS/Bedrock-AgentCore`：`CPUUsed-vCPUHours`、`MemoryUsed-GBHours`、`Sessions` |
| 全部删除 | `bash deploy/99_cleanup.sh` |

## 中国区注意事项

1. Runtime 入站鉴权只有 IAM 和非 Cognito 的 OIDC（CUSTOM_JWT）两种；宁夏没有 Cognito。
2. 没有 AgentCore Memory，跨会话记忆需自行存 DynamoDB。
3. VPC 模式要用**私有子网 + NAT**（或 ECR/S3/Logs 的 VPC 终端节点），公有子网会创建失败。
4. 镜像在境内构建推送更快（CodeBuild / 宁夏 EC2）；本地推 800MB 到宁夏约 13 分钟。
5. 对话内容会发给第三方 LLM，需评估数据合规；如不允许，改为 SageMaker 自托管模型并修改 `LLM_BASE_URL`。
